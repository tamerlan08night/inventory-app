# 14 ТЕМ УЧИТЕЛЯ — 14 КАРТОК

> Одна картка = одна тема. Кожна картка: **що це → де в мене → одне речення прикладу**.
> Більше нічого вчити не треба. Це і є відповідь на будь-яке питання зі списку.

---

### 1. React

**Що це:** JavaScript-бібліотека для побудови інтерфейсу з компонентів.
**Головне:** коли змінюється стан — React сам оновлює сторінку.
**Де в мене:** весь застосунок. CSS — окремо, у файлах `.css`, React його не замінює.

> «Без React мені довелося б вручну перемальовувати сітку після кожної дії — додав предмет, з'їв, змінив вагу — і легко щось забути оновити.»

---

### 2. Vite

**Що це:** інструмент, який запускає проєкт у режимі розробки й збирає його для браузера.
**Головне:** `npm run dev` — запуск, `npm run build` — фінальна збірка.
**Де в мене:** `vite.config.js` і `package.json`.

> «Vite дає мені швидкий dev-сервер з гарячим оновленням: змінив файл — сторінка оновилась сама. Для фіналу `build` збирає все у статичні файли.»

---

### 3. Components

**Що це:** функція, яка повертає розмітку (JSX).
**Головне:** компоненти вкладаються один в одного і повторно використовуються.
**Де в мене:** `App` → `ContentView` → `InventoryWorkspace` → `InventoryGrid`.

```jsx
// NavBar.jsx — компонент
export default function NavBar({ activeTab, onChange }) { ... }
```

> «Компонент — це як окремий блок сторінки. У мене їх близько двадцяти, і кожен відповідає за свою частину.»

---

### 4. Props

**Що це:** параметри компонента — дані, які передаються зверху вниз.
**Головне:** дитина не змінює `props` напряму; зміна йде через функцію-колбек.
**Де в мене:** `InventoryGrid` отримує `inventory` і `onMoveItem`, а не тримає свій список.

```jsx
<NavBar activeTab={activeTab} onChange={setActiveTab} />
```

> «Спільний стан лежить вище, у `App` і хуках, а вниз іде через `props`. Назад — через колбеки.»

---

### 5. useState

**Що це:** хук, який дає компоненту пам'ять.
**Головне:** повертає пару — значення і функцію зміни; зміна викликає перемальовку.
**Де в мене:** активна вкладка в `App`, модалки в `PlayerPanel`, інвентар у `useInventory`.

```jsx
const [activeTab, setActiveTab] = useState('inventory');
```

> «Звичайна змінна не перемальовує сторінку. `useState` зберігає значення між рендерами і оновлює UI при зміні.»

---

### 6. Events

**Що це:** реакція на дію користувача — клік, зміна інпута, перетягування.
**Головне:** в React це `onClick`, `onChange`, `onDrop` — функція, а не рядок.
**Де в мене:** кнопки вкладок, кнопка «з'їсти», drag & drop у сітці, форма DEV.

```jsx
<button onClick={() => onChange(tab.id)}>{tab.label}</button>
```

> «Подія — це просто функція. Я вішаю її на елемент, і React викликає її, коли користувач щось робить.»

---

### 7. Conditional Rendering

**Що це:** показувати різну розмітку залежно від умови.
**Головне:** `&&` — показати або нічого; тернарний `? :` — показати одне або інше.
**Де в мене:** `ContentView` вибирає вкладку, модалки рендеряться тільки коли відкриті.

```jsx
{isDevOpen && <DevSpawnModal onClose={...} onSpawn={...} />}
```

> «Модалка існує в DOM тільки коли відкрита — інакше її немає взагалі.»

---

### 8. Maps

**Що це:** метод масиву, який перетворює дані на список елементів.
**Головне:** кожен елемент потребує `key`, щоб React розпізнавав його між рендерами.
**Де в мене:** вкладки навігації, слоти сітки, хотбар, кнопки швидкості.

```jsx
{inventory.map((item, index) => (
    <div key={index} className="inventory-slot">...</div>
))}
```

> «`map` перетворює масив даних на масив JSX. Для фіксованих слотів індекс — прийнятний ключ.»

---

### 9. Objects with useState

**Що це:** стан може бути не одним числом, а об'єктом із багатьма полями.
**Головне:** об'єкт не змінюють напряму — створюють новий через `{ ...previous, поле: значення }`.
**Де в мене:** форма DEV (12 полів в одному об'єкті) і потреби в `useSurvival`.

```jsx
const setField = (field, value) =>
    setForm((previous) => ({ ...previous, [field]: value }));
```

> «Один об'єкт замість дванадцяти `useState`. Копія через `...` потрібна, бо React порівнює посилання, а не вміст.»

---

### 10. useEffect

**Що це:** хук для побічних дій **після** рендеру.
**Головне:** масив залежностей каже, коли запускати; `return` прибирає за собою (cleanup).
**Де в мене:** збереження в `localStorage`, таймер потреб, закриття модалок на `Escape`.

```jsx
useEffect(() => {
    const id = setInterval(tick, 1000);
    return () => clearInterval(id);
}, [survival.isFlowing, survival.speed]);
```

> «Без cleanup старі інтервали жили б далі, і вода з калоріями падали б швидше.»

---

### 11. React Router

**Що це:** бібліотека для сторінок із власними URL (`/inventory`, `/stats`) без перезавантаження.
**У проєкті:** не використав — у мене одна сторінка, а розділи перемикаються станом `activeTab`.
**Як би додав:** обгорнув би `App` у `BrowserRouter` і зробив `<Route path="/inventory" element={<InventoryWorkspace />} />`.

> «Мені це не було потрібно: вкладки — це той самий стан, тільки без адреси. Якби хотів посилання на конкретний розділ або кнопку "назад" — перейшов би на Router.»

---

### 12. Forms

**Що це:** введення даних користувачем — інпути, селекти, кнопка відправки.
**Головне:** у мене **контрольовані** поля: `value` зі стану, `onChange` оновлює стан.
**Де в мене:** модалка DEV — створення предмета з валідацією.

```jsx
<input value={form.name} onChange={(e) => setField('name', e.target.value)} />
```

> «React — єдине джерело правди: я можу перевірити значення, підсвітити помилку й скинути форму.»

---

### 13. Repository Pattern

**Що це:** патерн, коли доступ до даних винесено в окремий шар, а не розкиданий по компонентах.
**У проєкті:** окремого класу-репозиторію немає, але принцип частково є — `loadState` і `localStorage` зібрані в хуках, а не в компонентах.
**Як би зробив:** файл `repositories/inventoryRepository.js` з методами `load()`, `save()`, `clear()`.

> «Компонент не знає, звідки беруться дані. Зараз це `localStorage`; якби з'явився сервер — замінив би тільки репозиторій, а UI не чіпав.»

---

### 14. Local Storage

**Що це:** сховище в браузері, яке зберігає дані між перезавантаженнями.
**Головне:** зберігає тільки рядки, тому об'єкти проходять через `JSON.stringify` / `JSON.parse`.
**Де в мене:** інвентар, хотбар, спорядження і потреби.

```jsx
useEffect(() => {
    localStorage.setItem('rpg_inventory', JSON.stringify(inventory));
}, [inventory]);
```

> «Це не стан, а сховище: стан живе в пам'яті, а `useEffect` записує його на диск, щоб прогрес не зникав.»

## Якщо питання не з цього списку

> «Це реалізовано ось тут — покажу.»

І показуєш місце в коді, називаючи, що воно робить. Це не «не знаю», це відповідь через код.

## Дві чесні відповіді, які не втрачають балів

> «React Router я не використав — у мене одна сторінка. Але знаю, що це, і можу пояснити, як би додав.»

> «Repository Pattern у чистому вигляді немає. У мене його роль частково виконують хуки: доступ до `localStorage` зібраний там, а не в компонентах.»
